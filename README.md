# commentsh

**Comment Shell** — run shell commands from inside code comments.

`commentsh` scans text files for comment directives, executes the commands they reference, and
writes the output back into the file. It's a documentation generator, a `go:generate`-style task
runner, and a lazy way to keep any text file honest — all in one dependency-free Deno script.

## How it works

One directive, two forms: `cmd:` opens a block whose command output is injected into the file, and
`cmd!:` runs a one-line command as a side effect without touching the file.

### `cmd:` — inject stdout into the file

An opening comment names a command; everything between it and the closing comment is replaced by the
command's stdout. This is how you keep CLI help text, benchmark tables, and generated listings in
sync with your code.

The block below is live — commentsh regenerates it every time it runs on this file, so the example
always shows its own output:

<!-- cmd: echo This line is regenerated by commentsh on every run. -->

This line is regenerated by commentsh on every run.

<!-- /cmd -->

Command output that contains a directive-shaped line can't forge its own tags. Such lines are
escaped before injection — the comment open becomes `&lt;!--` for HTML files, `///` for
slash-comment files, and `##` for hash-comment files — so injected blocks always round-trip intact.

### `cmd!:` — execute a side effect, leave the file alone

A one-line directive that runs its command like `go:generate` would, streaming the output to your
terminal. The file is not modified. The `!` marks the command as fire-and-forget: with no closing
comment to fill, commentsh just runs it. The `!` must be glued to the keyword (`cmd!:` exactly — not
`cmd !:` or `cmd!!:`).

```go
// cmd!: sqlc generate
```

```python
# cmd!: pip install -r requirements.txt
```

## Comment syntax

commentsh auto-detects the comment syntax from each file's extension (or filename), so the same
directives work in every language in your repo:

| File type                 | Comment syntax | Directive example                         |
| ------------------------- | -------------- | ----------------------------------------- |
| Markdown, HTML, XML       | `<!--` `-->`   | `&lt;!-- cmd: deno task gen --&gt;`       |
| TypeScript, JS, Go, Rust  | `//`           | `// cmd: go run ./gen`                    |
| Python, Ruby, YAML, shell | `#`            | `# cmd!: pip install -r requirements.txt` |
| SQL, Lua                  | `--`           | `-- cmd: psql -f seed.sql`                |
| CSS, SCSS                 | `/*` `*/`      | `/* cmd: npx tailwindcss build */`        |

Unknown extensions default to HTML comments, which keeps directives invisible in rendered Markdown.
Files without extensions (`Dockerfile`, `Makefile`, `.gitignore`, …) are matched by name.

Directives must appear at the start of a line and commands run through the platform shell (`sh -c`
on Unix and macOS, `cmd /c` on Windows), so quoting rules follow that shell.

## Usage

Run it on files or directories:

```bash
deno run --allow-read --allow-write --allow-run commentsh.ts README.md
deno run --allow-read --allow-write --allow-run commentsh.ts src docs
```

Or straight from GitHub, without cloning:

```bash
deno run --allow-read --allow-write --allow-run \
  https://raw.githubusercontent.com/EthanThatOneKid/commentsh/main/commentsh.ts \
  README.md
```

Wire it into your task runner so developers never have to think about it:

```json
{
  "tasks": {
    "docs:gen": "deno run --allow-read --allow-write --allow-run commentsh.ts README.md",
    "docs:check": "deno run --allow-read --allow-write --allow-run commentsh.ts --check README.md"
  }
}
```

### Watching while editing

Use the runtime's watch flag instead — commentsh no longer ships its own watcher:

```bash
deno run --allow-read --allow-write --allow-run --watch=README.md commentsh.ts README.md
```

`--watch=<file>` restarts the process when the file (or the script) changes, so generated docs stay
live while you edit. Commands whose output changes on every run (timestamps, hashes) will re-trigger
a restart each time, so keep injected output deterministic.

### Previewing changes

`--diff` runs every directive without writing, printing what each changed `cmd:` block would look
like, and exits 1 if anything would change:

```bash
commentsh --diff README.md
```

The diff is block-scoped: each changed block shows its removed and added lines under the opening
comment's line number, so prose edits elsewhere in the file stay out of the way. For a whole-file
view, run commentsh normally and inspect the result with `git diff`.

### Checking for stale docs in CI

`--check` runs every directive but refuses to write files, exiting with code 1 if anything would
change. Fail the build whenever a developer changes command behavior but forgets to regenerate:

```yaml
- run: deno run --allow-read --allow-write --allow-run commentsh.ts --check README.md
```

Each stale block is reported by line number and opening tag, so a failure shows exactly what
drifted:

    out of date: README.md
      line 23 (<!-- cmd: echo This line is regenerated by commentsh on every run. -->)

Or use the reusable [commentsh check action](.github/actions/check-commentsh/action.yml) — the same
check with zero setup, inputs for `files` and a `version` ref, and `changed`/`stale-files` outputs:

```yaml
- uses: EthanThatOneKid/commentsh/.github/actions/check-commentsh@main
  with:
    files: |
      README.md
      docs/CLI.md
```

## CLI reference

```
commentsh [OPTIONS] <FILE|DIR>...
```

| Option            | Description                                                                      |
| ----------------- | -------------------------------------------------------------------------------- |
| `--check`         | Do not write files; exit 1 if any file would change (use in CI).                 |
| `--diff`          | Do not write files; print the block changes and exit 1 if any file would change. |
| `-h`, `--help`    | Print help and exit.                                                             |
| `-V`, `--version` | Print the version and exit.                                                      |

Exit codes: `0` success (or everything up to date with `--check`/`--diff`), `1` a command failed / a
directive is malformed / stale docs, `2` invalid usage.

## Design notes

- **Idempotent.** Running commentsh twice produces the same file. The generated blocks in this
  README are deterministic for this reason.
- **Dependency-free.** A single script, no imports, no `node_modules`. Runs from any URL or
  checkout.
- **Fail loud.** A failing command or a `cmd:` block missing its closing comment stops that file
  with a clear error and a non-zero exit code.
- **Deterministic ordering.** Directives execute in file order, so later directives can depend on
  side effects from earlier ones.
- **No nesting.** A directive inside a `cmd:` block is treated as block content. A `cmd:` block
  whose closing comment never arrives is an error, and commands are single-line.
- **Safe by default.** Directives only match at the start of a line, and binary files are skipped.
  Note that, like `go:generate`, commentsh scans raw text — a `cmd:`/`cmd!:` string in a string
  literal will still execute.
